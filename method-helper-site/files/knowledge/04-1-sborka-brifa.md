# Этап 4.1 — Сборка брифа

> Этап 4 разбит на две части: **4.1 Сборка брифа** (этот файл) и **4.2 Генерация** (`04-2-generaciya.md` — шторминг и докрутка). Здесь — подготовка, та самая «бо́льшая часть работы»: собрать культурный материал и упаковать его в один экран. На выходе — готовый одностраничный бриф (текстовый или визуальный), с которым человек идёт штормить на 4.2.

## Цель этапа
Простыми словами: под выбранные на синтезе смыслы/противоречия собрать весь материал для шторминга на одном экране — боли людей дословными цитатами + культурный и продуктовый материал + три вопроса докрутки. Это и есть **одностраничный бриф (One-Page Brief)** — сердцевина Метода.

Главная мысль: **идею нельзя выжать из пустого листа — её надо подготовить.** Если есть 10 часов на идею, 9 уходит на изучение и сборку брифа, и только час — на сам шторминг (этап 4.2). Ступор почти всегда не от нехватки таланта, а от нехватки информации. От того, чем наполнишь бриф, зависит, что получишь: большую идею, промо-активацию, сервис или продукт.

## Шаги
1. Ресёрч по мемам, культуре, объектам — под выбранные направления
2. Собрать одностраничный бриф (One-Page Brief): текстовый и/или визуальный
3. Оформить бриф в HTML — на один экран, по эталонному формату (см. «Формат HTML-брифа»)

## Длительность
~1–1,5 дня (ресёрч + сборка брифа + вёрстка). Бриф алгоритмичен — черновик можно отдать ИИ.

## Примеры
*(Денис добавит примеры — собранные брифы. Показывать по запросу: «показать пример?».)*
Сквозной кейс — велофонд Orange County: под выбранные направления собирали мемы про велосипедистов, знаковые объекты региона, велосипедную фактуру (как клеят имена на раму, разметка) → собрали 6 одностраничных брифов в HTML (противоречия «имидж vs защита», «братство vs дикие» и др.) → шторминг (Method 3, 016).

## Советы
- **Бриф собирай заранее, не штормь с нуля.** Без подготовки шторминг — как копать яму лопатой в случайном месте; с брифом — есть карта и инструменты, копаешь точечно (Method 2).
- **Цитаты — дословно, без сокращений.** Читатель брифа должен увидеть весь контекст, который у тебя в голове. Сократил/обобщил — потерял контекст и силу.
- **Один объект в одной ячейке.** Серые блоки — это отдельные «детали», которые потом соединяешь с болями. Запихнул два в одну — нечего комбинировать.
- **Конкретика рождает решение.** Пока серые блоки общие («приложение») — рождаются общие идеи. Конкретный объект («очки Ray-Ban», «дроп лимитки как Supreme») — сразу даёт зацепку.
- **Можно ускорить ИИ.** Брифы алгоритмичны — черновик контента можно отдать в чат-бот, а вёрстку собрать по готовому шаблону (см. ниже).

## Можно ли пропустить этот этап?
- **Нельзя пропустить целиком** — без брифа шторминг (4.2) разваливается: мало идей, абстракции, выгорание. Это и есть «страх белого листа».
- **Можно сжать ресёрч** (шаг 1), если направление узкое и культурный материал уже есть с этапа исследования. Но сборку брифа (шаг 2) не урезаем.

## Планирование
3 вопроса: **один или с кем? · сколько людей? · сколько времени?** → короткий план из «Деталей»: что оставить / сжать / выкинуть + риски. Детали в ответе не разворачивай.

## Детали шагов  *(служебное — по умолчанию не показывать)*

### Шаг 1 — Ресёрч по мемам, культуре, объектам (под направления)
- **Тайминг:** ~1–2 дня (большую часть Денис делает сам через ИИ).
- **Критичность:** можно сжать (но не выкинуть для больших идей).
- **Риск при урезании:** без культурного слоя идеи получаются «голыми», без эмоционального пласта; визуальный бриф собрать не из чего.
- **Параллелится:** да — мемы/объекты раздать по людям, технологии копить как базу насмотренности.
- **Как делать:** под уже выбранные направления собрать три вещи: (1) мемы/анекдоты/приколы по теме, (2) знаковые объекты и пространства региона (памятники, наружка, места), (3) фактуру вокруг самого продукта/темы. Складывать с визуальным подтверждением, не «из головы». Это сырьё для серых блоков брифа.
- **Сделано хорошо, если:** под каждое направление есть набор мемов + объектов + предметной фактуры с картинками. *Ошибки:* собирать абстрактно, не под конкретное направление; брать «из головы» без пруфа; пропустить — и потом нечем наполнить бриф.
- **Детальный материал:**
  - Денис вслух про велобриф: «первое — мемы, второе — какие-то знаковые объекты, пространство, наружка и прочее. Третье — что-то связанное с велосипедом… как на велосипедах наклеивают имена, или дорога, или разметка — всё, что около-велосипедная история, с которой мы можем повзаимодействовать» (Method 3, 016).
  - Ищем «точки, притягивающие большое внимание» ИЛИ смыслово связанные с брифом; культурные события привязывать к локации брифа (Method 3, 016).
  - **Ускорить с ИИ:** есть авторский MD-промпт культурного ресёрча (поиск культурного напряжения), оптимизированный «под любую нейронку с учётом её памяти», сам аранжирует противоречия — `[промпт будет — Денис выкладывает]` (Method 3, 016).

### Шаг 2 — Собрать одностраничный бриф (One-Page Brief)
- **Тайминг:** ~0,5 дня (бриф алгоритмичен; черновик можно отдать ИИ).
- **Критичность:** ядро (без этого этап 4.2 разваливается).
- **Риск при урезании:** штормишь с нуля → мало идей, абстракции, выгорание.
- **Параллелится:** частично — шаблоны общие, наполнение можно раздать.
- **Как делать:** собрать ВСЁ для шторминга на одном экране. Есть две вариации:
  - **Текстовый бриф** (структурнее, лучше для активаций): жёлтые стикеры = боли-цитаты из интервью + серые блоки = точки контакта/фичи/объекты + внизу три вопроса докрутки.
  - **Визуальный (фото-)бриф** (лучше для больших, глубоких идей): вместо серых блоков — картинки: культура/мемы, медиа, продукт, технологии.
- **Сделано хорошо, если:** на одном экране собраны 8–12 жёлтых болей (дословные цитаты, можно с факт-карточками) + серые блоки/картинки + три вопроса; названия идей хлёсткие, отражают суть. *Ошибки:* сокращать/обобщать цитаты вместо дословных; мало жёлтых (2–3) — нечего комбинировать; путать, какой бриф под какую задачу.
- **Детальный материал:**
  - **Структура серых блоков** (Method 3, 013): (1) сам продукт — диджитал или оффлайн (приложение и его фичи; для магазина — пакеты, чеки, кассы, этикетки); (2) популярные диджитал-сервисы (Яндекс.Карты, Spotify — то, чем люди пользуются); (3) медиа-сервисы по теме (блоги, инфлюенсеры, СМИ, газеты); (4) **блок «несвязанного»** — вещи, принципиально НЕ связанные с темой («ты намеренно пытаешься придумать что-то, что никак не связано» — даёт вырваться за рамки).
  - **Три вопроса докрутки** дословно (Method 3, 013): «как эту идею реализовать в приложении/продукте? как превратить в сервис/услугу? что добавить, чтобы попала в заголовки газет?». Последний (PR) — **must**, всегда оставлять. Вопросы можно менять под задачу (для ролика — «как это в драме / комедии / мультфильме»), но не больше трёх.
  - **Эволюция OPB** (Method 2): раньше брифы были 45–50 страниц — информация терялась, когда команда уходила штормить. OPB концентрирует всё в один экран.
  - **Два брифа — разные задачи** (Method 3, v2): «фото-бриф даёт больше — с фотографии считываешь обстановку, вещи»; НО «если ты сам аудитория, текст наталкивает на такие же глубокие ассоциации». В фото-брифе нет заголовка-сообщения — отталкиваешься от любой картинки.

### Шаг 3 — Формат HTML-брифа (эталон)
- **Тайминг:** ~0,5–1 ч на бриф, если контент готов (вёрстка по шаблону).
- **Критичность:** оформление — но именно оно делает бриф «одним экраном», который удобно штормить и не стыдно показать.
- **Как делать:** контент из шага 2 разложить по модели ниже и подставить в готовый HTML-шаблон. Один бриф = один HTML = один экран (board 1400px). Открывается в браузере, печатается/экспортится в картинку.

**Когда нужен HTML-формат:** под клиентские/презентационные брифы и под пакет тем (как на интенсиве — 6 брифов одним стилем). Для быстрого личного шторминга достаточно стикеров/Miro — HTML не обязателен.

**Дизайн-система** (стиль лендинга Method Intensive):
- Шрифты Google Fonts: **Inter Tight** (текст) + **Instrument Serif** italic (заголовок-цитата).
- Палитра: фон `#f4f1ea`, «бумага» `#fffdf7`, чернила `#14140f`, **жёлтый (боль)** `#ffd84d`, **оранжевый (акцент/вопросы)** `#ff5436`, жёлтая цитата `#fef9e3`, серый блок `#ecebe3`.
- Раскладка board 1400px: `meta` (шапка) → `title-bar` (жёлтая плашка с заголовком-цитатой) → `desc` (абзац контекста) → `quotes-grid` (4 колонки) → `examples-grid` (5 колонок) → `questions` (3 колонки).

**Модель контента одного брифа:**
- **meta-шапка:** слева «`NN / 06` · [Название проекта] · Метод · Тип 1»; справа «[Код темы, напр. Противоречие C1 / Драйвер D1 / Барьер B2] · Σ=NN» (Σ — суммарный балл темы из синтеза, если считали).
- **Заголовок-цитата** (`title-bar`, Instrument Serif italic): суть конфликта без метафор. Для противоречия — формула **«Хочу X ↔ Хочу Y»** (например: «Хочу выглядеть круто и „своим“ ↔ Хочу вернуться домой живым»). Для драйвера/барьера — одна ёмкая формулировка боли.
- **desc** — абзац контекста (1 экран, ~3–5 предложений): в чём конфликт, с цифрами. Факты выделяй `**жирным**` (рендерится жёлтым маркером).
- **quotes-grid (12 ячеек = 10 + 2):**
  - **10 жёлтых цитат** — дословные боли из интервью, каждая с подписью автора («…» — Имя / S07). НЕ сокращать.
  - **2 факт-карточки** (пунктирные, отличаются от цитат) — цифра/факт из ресёрча; ключевое число оборачивай в `[[…]]` (рендерится крупным оранжевым). Пример: «Шлем снижает риск травмы головы на `[[~60%]]`…».
- **examples-grid (30 серых блоков = 6 тем × 5):** по **ОДНОМУ объекту в ячейке**. Шесть тематических групп (это и есть «серые блоки» Метода, развёрнутые):
  1. **Идеи-активации** — конкретные форматы под тему (дизайн-коллаб, дресс-код на коферайде, дроп лимитки…).
  2. **Продукты / объекты желания** — что можно сделать предметом (шлем как объект желания, кастомная окраска, фирменная джерси…).
  3. **Культурные объекты / субкультуры** — знаковое для аудитории (велокурьерская субкультура, alleycat, фестиваль…).
  4. **Диджитал-сервисы** — чем люди пользуются (Strava, TikTok, Pinterest, ресейл-площадки…).
  5. **Медиа** — где про это говорят (Hypebeast, профильный YouTube, форумы, местные новости…).
  6. **Несвязанное / аналогии** — намеренно из другой области (очки Ray-Ban как «защита, ставшая модой», ремень безопасности, сникерхеды…) — даёт вырваться за рамки.
- **questions (3 ячейки, оранжевые):** три вопроса докрутки. Дефолт: «Как из этого сделать сервис?» · «Как из этого сделать продукт?» · «Как сделать так, чтобы об этом написали газеты?». Третий (PR) — must.

- **Сделано хорошо, если:** бриф помещается в один экран 1400px; 10 дословных цитат + 2 факта; 30 серых блоков по одному объекту; заголовок — реальный конфликт «два хочу», а не лозунг; шрифты подтянулись с Google Fonts. *Ошибки:* перегруз ячейки (два объекта); сокращённые цитаты; заголовок-метафора вместо сути; больше трёх вопросов.

## Как вести человека по этапу  *(интерактив для ассистента)*

Принцип: человек **даёт** (направления + цитаты с синтеза) — ты **сам выдаёшь готовый артефакт** (ресёрч, бриф, HTML), он правит/утверждает, дальше. Рассуждение — про себя, в ответ только результат.

**Шаблон шага:** 1 строка «что делаем» → (если надо) попроси материал → выдай артефакт → «ок или поправить?» → дальше.

**Артефакт на каждом шаге:**
- **Ресёрч:** под выбранные направления сам набросай списки — мемы/приколы + знаковые объекты региона + фактуру вокруг продукта → «что добавить?».
- **Бриф:** собери сам One-Page Brief — 8–12 жёлтых болей (дословные цитаты) + серые блоки (6 тем) + три вопроса. Под активации — текстовый, под большие идеи — визуальный. «Что поменять?».
- **HTML:** по утверждённому контенту собери готовый HTML по шаблону выше (или JSON под пакет тем) → отдай файл. «Открой в браузере — ок?».

**Лекции:** на входе в этап и на шаге брифа напомни «есть лекция „Одностраничный бриф“ — дать?».

**В конце:** отдай готовый бриф (HTML/текст) и переходи на **4.2 Генерация** — с этим брифом идём штормить. Если меняется чат — собери хендофф (бриф + направления).
**Перед стартом:** 3 вопроса планирования + проверь, есть ли выбранные на синтезе направления и отобранные цитаты.
